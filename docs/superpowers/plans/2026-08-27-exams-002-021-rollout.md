# Exams 002–021 Rollout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Author, independently oracle-check, gcc-verify, build, index, and publish twenty distinct practice exams from the approved specs.

**Architecture:** Each exam is authored in its permanent isolated exams/R/pages-src archive and validated without touching shared scratch. A single integrator then copies that exam's six runtime fragments into pages/src, runs the real verifier, builds pages/N/index.html, adds its landing card and local catalog row, commits, pushes, and checks the live page before the next exam begins. This atomic loop keeps every completed exam usable if execution later pauses.

**Tech Stack:** HTML, JavaScript, JSON, C99, Python 3.13 brute-force oracles, Node.js 22, Compiler Explorer gcc 13.2, GitHub Pages.

## Global Constraints

- Execute this plan only after the generic-driver infrastructure plan passes in full.
- specs 002–021 are approved; do not redesign or change their signatures.
- Backtracking is excluded.
- No printIDontKnow reveal and no solutions on the paper.
- Model solutions appear only through the post-submission solutions button.
- Never create per-exam copies of pages/src/_template.html.
- Generate every _tests.json expectation from an independent Python oracle.
- Include every worked example, edge cases, several larger random cases, and at least twelve cases per question.
- Run node verify.mjs against gcc 13.2 before building any page.
- Only the integration task may write pages/src or pages/2 through pages/21.
- Pass unpadded page numbers 2 through 21 to build.mjs.
- The pages directory is the only Git repository. exams archives and exams/README.md are local permanent artifacts outside that repository.
- Never leave a completed exam unpublished: after its archive and gcc verification pass, build it, update both catalogs, commit, push, and require a live HTTP 200 page containing godbolt.org and exam-tests before authoring the next exam.

## Atomic Deployment Override

The numbered batch tasks below describe ownership and review boundaries, but
their exams execute one at a time. For each N=2..21, complete the authoring
steps for only that exam, immediately execute Tasks 5 and 6 for that exam,
commit and push the resulting page/card, verify the deployed URL, and only
then resume the batch with N+1. No completed archive may wait for the rest of
its batch before publication.

~~~js

import assert from "node:assert/strict";
import fs from "node:fs";
import os from "node:os";
import path from "node:path";
import {validateArchive} from "./check-archive.mjs";

test("accepts a complete isolated archive", () => {
  const dir = fs.mkdtempSync(path.join(os.tmpdir(), "exam-archive-"));
  for (const name of ["_meta.json","_paper.html","_skeletons.js","_tests.json","_q1key.txt","_solutions.js"]) {
    fs.copyFileSync(new URL("./" + name, import.meta.url), path.join(dir, name));
  }
  fs.writeFileSync(path.join(dir, "_oracle.py"), "print('ORACLE OK')\n");
  fs.writeFileSync(path.join(dir, "notes.md"), "Oracle reproduced all worked examples.\n");
  assert.deepEqual(validateArchive(dir, {minimumCases:12}), []);
});
~~~
